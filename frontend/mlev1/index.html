§ 02 — Architecture

One pipeline,
two synchronized stores.

Raw transactions flow through a single batch pipeline that writes both stores from the same definition — so the offline (training) and online (serving) paths never diverge.

Offline · PostgreSQL 15

Full feature history for training and backfills. Built for large analytical scans, not latency.

Online · Redis 7

Latest feature values keyed by user. Sub-millisecond reads to keep live inference fast.

Kept in sync

One pipeline writes both stores from a single definition — training and serving can't drift apart.
